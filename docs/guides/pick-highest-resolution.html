同一张图多个分辨率，怎么挑最清晰的

图库与内容站为了让同一张图在缩略图、正文、灯箱等位置都能用，通常会给它准备多个不同尺寸的地址。 抓取时这些版本会全部进入列表，肉眼几乎分不清哪条才是原图。这篇教程介绍两种互补的做法： 用「清晰度排序」把细节最多的那版顶到最前，用「归并相似图」把同一张图的多个版本折叠成一条， 默认只展示最清晰的那版。两种计算都在你自己的浏览器里完成，不联网、不上传。

为什么同一张图会出现很多个版本

常见来源有三种，它们对应的地址往往只差几个参数：

  • 同一路径的不同尺寸后缀，例如 _thumb、_medium、_large。
  • CDN 的尺寸与裁剪参数，例如 ?w=200 与 ?w=1600——同一张图被请求了两次，因此两条都会被记录。
  • 响应式图片：页面用 srcset 声明多个候选地址，浏览器按当前屏幕密度挑选要加载的那一个。

因为扩展是「看到什么记什么」，这些版本都会如实进入列表——这是特性而不是缺陷：只有都记录下来， 你才有机会挑到最大的那版。问题在于，平铺的列表并不能告诉你哪条最大。

按清晰度排序，把最清晰的那版顶上来

  1. 打开弹窗，点漏斗图标展开筛选面板。
  2. 在「排序」里选「清晰度」。
  3. 列表会按清晰度分数从高到低重排，细节最丰富的那版排在最前面；分数相同（通常是还没算过）的条目按捕获时间回落排序。

第一次切换时会看到「分析中 x/y」的进度提示：清晰度需要实际读取图片像素才能算，扩展会逐张分析， 因此图片较多时需要等一会儿。已经算过的条目不会重复分析，切回「捕获时间」排序可以随时恢复原来的顺序。

排序是按当前筛选结果整体重排的，所以你可以先按「最小尺寸」筛掉小图，再按清晰度排序， 这样列表顶部就是真正值得保存的那几张。

归并相似图，一次只留一条

如果同一张图的版本特别多，逐个比较仍然费事，这时用「归并相似图」：

  1. 在筛选面板里勾选「归并相似图」。
  2. 扩展会逐张分析图片，把它们按内容相似度分组；同一张图的不同分辨率会被折叠成一组。
  3. 组头显示「相似 N 张」，默认只展示组内最清晰的那一条；点击组头可以展开查看其余版本。

与无法比较的条目（例如跨域读取失败、或还没分析过的图）都会各自独立显示，不会被误并入某一组。 另外，归并视图与「按页面分组」互斥：开启归并后「按页面分组」按钮会变为不可用， 鼠标悬停可以看到说明，关掉归并即可恢复。

这些分数是怎么算出来的

两件事都在本地算：相似度用感知哈希（把图片缩成小图后比较相邻像素的明暗关系， 得到一串指纹，两张图指纹的差异位数越小越相似，算法思路见 Perceptual hashing 词条）， 清晰度用灰度图的拉普拉斯方差（把每个像素与它上下左右邻居做比较，边缘越多、细节越多， 分数越高；纯色与模糊图的分数接近 0）。

计算发生在扩展的后台文档里，按需触发、逐张串行处理，图片会先被缩小再计算，因此大图也不会拖慢整体速度。 整个过程不发起任何数据上报——图片只在你的浏览器里被读取一次像素，随后丢弃， 这一点与隐私政策中的说明一致（见隐私政策）。

误合并或漏合并时怎么办

  • 两张不同的图被并成一组：多数出现在本身就很相似的同系列图上（例如同一组连拍或同一套插画）。可以展开分组逐条查看，把确实不需要的移除。
  • 同一张图的多个版本没有被并到一起：如果某个版本经过了明显裁剪或加了水印，指纹差异会变大，从而被判定为不同的图。
  • 想完全避免误判：关掉「归并相似图」，改用「按清晰度排序」逐条挑选——两者是独立的，归并不影响排序。
  • 有稳定的复现样本：欢迎带上截图与页面地址，在 GitHub Issues 反馈，相似度阈值需要真实样本才能调准。
